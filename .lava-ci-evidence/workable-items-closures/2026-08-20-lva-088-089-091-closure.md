## LVA item mapping and closure decision

### LVA-088 — Video #7 — 'Choose your API' shows 'lava.app:7777' preset + mislabeled 'On this network'

- **Covering Challenge:** `Challenge64ApiDiscoveryScreenFriendlyNamesTest`
  (KDoc marker `// covers-changelog: LVA-088`)
- **Both test methods PASS** on the real device run above:
  `cloudPresetLabeledHonestly_notOnThisNetwork` (confirms the cloud/remote
  preset is labeled "Cloud / remote server", never "On this network") and
  `discoveredApi_showsFriendlyName_notGenericLabel` (confirms a discovered
  API with an advertised mDNS name renders that name, not a generic label).
- **Decision: CLOSE as `fixed`.** The Challenge drives the real production
  `ApiSelectionStep` composable (the same one `OnboardingScreen` instantiates)
  and asserts on rendered UI text — genuine device confirmation, not an
  inherited claim.

### LVA-089 — Video #8 — mDNS-discovered API shows raw IP 192.168.0.107:8443 with no friendly name

- **Covering Challenge:** `Challenge65MdnsShowsFriendlyNameTest`
  (KDoc marker `// covers-changelog: LVA-089`)
- **Test method `discoveredIpApi_rendersFriendlyName_notRawIp` PASSES** on
  the real device run above — asserts the friendly name is the primary
  label and that no node renders the bare raw IP:port as a standalone
  primary label.
- **Decision: CLOSE as `fixed`.** Same production `ApiSelectionStep`
  composable, real rendered-text assertions, genuine device confirmation.

### LVA-091 — Video #10 — App-ID co-mingling (debug .dev + release both labeled 'Lava') — UNCONFIRMED in video

- **Covering Challenge:** `Challenge67AppIdSeparationTest`
  (KDoc marker `// covers-changelog: LVA-091`)
- **Root-cause fix (this-plan Task 2, commit `b540bb56`):** the Challenge's
  `appLabel_...` test method originally asserted the WRONG expected label
  (`"Lava"`) for the debug build — i.e. the TEST was wrong, not the
  production code. `app/src/debug/res/values/strings.xml` has overridden
  `app_name` to `"Lava DEV"` since the April 2026 rebrand (commit
  `6de017e4`), predating the original (wrong) test by ~2 months. Task 2
  renamed the method to `appLabel_debugVariantIsDistinctFromRelease` and
  corrected the expected value to `"Lava DEV"`.
- **Both test methods PASS** on the real device run above:
  `debugBuild_hasDevApplicationIdSuffix` (confirms the running package is
  `digital.vasic.lava.client.dev`, distinct from the release
  `digital.vasic.lava.client`) and `appLabel_debugVariantIsDistinctFromRelease`
  (confirms the resolved application label is `"Lava DEV"`, distinct from
  the release label `"Lava"`).
- **Decision: CLOSE as `fixed`.** The operator's video #10 observation
  ("both debug and release labeled 'Lava'") is genuinely NOT reproduced —
  debug and release ARE visually distinguishable by applicationId AND by
  display label, confirmed on a real device via
  `InstrumentationRegistry`-read package identity + `PackageManager`-resolved
  label (not mocked). Root cause: the video's premise was already false by
  the time it was recorded; the bug that WAS real was in the test's
  assertion (fixed by Task 2, commit `b540bb56`), not in production code.

## Not closing any workable item for Challenge72

`Challenge72SameDeviceMdnsDiscoveryTest` (recovered by Task 3, commit
`4b9141ce`) is NOT tied to any of LVA-088/089/091 — it is a bonus
same-device mDNS cross-app discovery Challenge. It cleanly **SKIPPED** via
its documented `assumeTrue` precondition: the api-app debug APK was not
installed on the target AVD (`scripts/run-challenge-matrix.sh` only
provisions the single `:app` APK via its `--apk` flag; the Containers
`cmd/emulator-matrix` CLI's `-apk` flag is likewise single-APK; and the
host-direct `adb install` path this Challenge's KDoc names as the
alternative is mechanically blocked on this host by
`scripts/hooks/guard-forbidden-commands.sh` §6.X guard for anything other
than the operator's authorized physical-device serial). This is a genuine,
honest SKIP — not a bluffed PASS, and not treated as one. No workable item
is closed on the strength of this result, per the task brief's explicit
instruction.
