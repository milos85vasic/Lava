**Root cause investigation performed before trusting the first result
(this project's Iron Law: no fixes/conclusions without investigation
first).** The FIRST attempt at this gate (on a container that had been
running continuously for 13 hours across many earlier test cycles this
session) reported `Challenge06CopyKeyTest` FAILING — clipboard empty after
tap — reproducibly, even after a plain Android-guest reboot. Since neither
of this cycle's actual changes (a version bump + a Go-only backend fix)
touch any Compose UI or clipboard code, and the SAME test had a genuine
PASS attestation from the previous day
(`.lava-ci-evidence/api-app-0.2.12-25-device-gate/Challenge06CopyKeyTest/`,
`test_passed: true`, fresh emulator), the stale 13-hour container was the
suspect. Stopped + removed it entirely and re-ran via the sanctioned

§6.X/§6.I). Result: clean PASS on the fresh boot — confirming the failure
was container/environment degradation from extended reuse across this
session's many test cycles, not a product regression.
