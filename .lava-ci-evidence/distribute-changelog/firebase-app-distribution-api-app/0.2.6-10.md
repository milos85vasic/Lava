## Lava-API-App-0.2.6-10 — 2026-06-13 (Public provider catalogue — onboarding can read providers from a freshly-discovered API)

**Previous published:** Lava-API-App-0.2.5-9 (debug+release).

- **Provider catalogue is now public** — the embedded on-device API serves its
  provider list (`GET /providers`) without requiring the Lava-Auth header, exactly
  like the health/readiness probes. This is what lets the Lava client read the
  provider list during onboarding against an API it has just discovered on the
  network (and therefore has no pre-shared key with yet). Previously this endpoint
  was behind the auth gate, so the client got HTTP 401 and fell back to the
  built-in providers with a "Couldn't reach the selected API" notice.
- **Per-provider operations remain authenticated** — only the non-sensitive
  catalogue listing was opened; search/download under `/v1/<provider>/…` still
  require a valid Lava-Auth key. (Proven by a real-binary test that asserts the
  three-way boundary: unauth `/providers` → 200, unauth `/v1/…` → 401, authed
  `/v1/…` → crosses the gate.)

Shares the exact `router.Build` construction with the standalone lava-api-go
binary (DRY) — the same one-line registration-order fix covers both surfaces.
