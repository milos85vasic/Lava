# Lava-API-App-0.2.0-4 — 2026-06-04 (Cross-app linking + idempotent start)

**Previous published:** Lava-API-App-0.1.2-3 (debug).

New feature — the on-device Lava API app now links with the Lava client:

- **Auto-start on request**: when the client opens the API app to "start the API", the engine
  starts automatically and the screen shows the live running state ("API running").
- **"Back to Lava client" / "Open Lava client"** button: returns to the client (which then
  auto-connects over loopback), or installs the client via the Firebase download page if it
  isn't present (no dead Play-Store links).
- The API app exposes its access key to the genuine, same-signature client via a
  signature-permission ContentProvider (no other app can read it).

Fix (operator-reported 2026-06-04, verified on a real Samsung S23 Ultra):

- **Bug B — "listen 0.0.0.0:8443; bind: address already in use"** when re-opening the API app
  while it was already serving. Root cause: every "start" request re-bound the listener.
  Fixed — start is now **idempotent**: a redundant start surfaces the live running state and
  never re-binds (so "Open Lava API app" always shows the current API, never crashes it).
