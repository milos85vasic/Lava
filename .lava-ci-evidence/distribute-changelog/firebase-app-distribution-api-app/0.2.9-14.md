## Lava-API-App-0.2.9-14 — 2026-06-14 (Key handoff fixed → client search authenticates)

**Previous published:** Lava-API-App-0.2.8-12 (debug+release).

- **The on-device API now hands its access key to the Lava client correctly** — the
  key-handoff ContentProvider (`ApiKeyProvider`) used to cache its key/port lookups in
  `onCreate()`, but Android runs a ContentProvider's `onCreate()` BEFORE the app's own
  `onCreate()` populates those values, so the provider served an empty cursor forever.
  The client therefore never received the API's per-instance key and every auth-gated
  `/v1/{provider}/search` request was rejected — search appeared completely broken.
  The provider now resolves the running key/port lazily on each request, independent of
  startup ordering. This is the on-device-API half of the end-to-end search fix.

Device-verified on a Genymotion Pixel 9 / API 35 VM: the R8 release on-device API serves
the matched release client, which completed a live search returning real results.
Foreground service (specialUse) unchanged from 0.2.8-12. Paired with client 1.3.9-1066.
