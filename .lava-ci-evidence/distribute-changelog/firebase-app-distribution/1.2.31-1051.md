**Previous published:** Lava-Android-1.2.30-1050 (debug + release both distributed earlier 2026-05-18).

**User-visible release:** NEW first-step onboarding screen + a small subtitle-rendering bugfix.

### What landed

1. **NEW: API Selection step in Onboarding (60th §6.L invocation, operator-directive)**
   - Inserted as the first interactive step between Welcome and Providers.
   - Uses the existing `LocalNetworkDiscoveryService` (mDNS NSD for `_lava-api._tcp` + `_lava-api-dev._tcp`) to surface live-discovered APIs as a tappable list.
   - On selection, runs the existing `ConnectionService.isReachable(Endpoint)` probe — same probe that drives the green-icon next to endpoints in the Connections list.
   - On probe success, persists the selected endpoint via `EndpointsRepository.add()` so the rest of the app routes through it, then advances to Providers.
   - On probe failure, surfaces the reason + "Try again" button so the user can retry or pick a different API.
   - "Search again" button re-triggers discovery if nothing was found.
2. **FIX: Provider subtitle rendering — "Form Login" / "Api Key" / "None" (was: `FORM_LOGIN` / `API_KEY` / `NONE`)**
   - Operator-flagged: subtitles under each Provider title rendered the raw enum name with underscores.
   - Fix: new `AuthType.displayLabel()` extension that word-splits + title-cases the enum.
   - 6-fixture unit test under `feature/onboarding/src/test/.../util/AuthTypeDisplayTest.kt` — including a forward-compat `every_enum_value_renders_underscore_free` test that catches any future enum value introducing an underscore.
3. **§6.L 60th invocation** recorded in CLAUDE.md per the standing-mandate-wall invariant.
