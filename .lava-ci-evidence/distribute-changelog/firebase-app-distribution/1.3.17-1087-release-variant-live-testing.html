Scope

Substantially broader than the previous cycle's minimum: 11 client Challenges + all 7 api-app Challenges, run against BOTH the debug and the R8-minified releaseTest build types, on a containerized KVM emulator (CZ_API34_Phone, API 34, phone).

Real defects found and fixed this pass

  1. androidx.compose.ui.test.testManifest was debugImplementation-only in both app/build.gradle.kts and api-app/build.gradle.kts. Since releaseTest is a distinct build type from debug, it never inherited this dependency, so any Challenge using the isolated createComposeRule() pattern (e.g. Challenge07/08) failed with Unable to resolve activity for ... ComponentActivity. Fixed by adding a matching releaseTestImplementation declaration in both files. A follow-up audit (dedicated subagent, read-only) confirmed this was the only debugImplementation dependency either app needed for androidTest — the one other candidate (LeakCanary) is genuinely unused by any androidTest code.
  2. Investigated a serious-looking finding down to ground truth via direct dexdump inspection of the actual signed release APK, matching this project's own LVA-098-incident methodology: CrossTrackerFallbackModalKt (a production Composable) was absent from the release APK's dex files. Confirmed via targeted dex searches that the SDK layer (CrossTrackerFallbackPolicy, SearchOutcome$CrossTrackerFallbackProposed), the network layer (SwitchingNetworkApi), and — critically — the ViewModel layer (SearchResultViewModel$onFallbackAccept$1/$onFallbackDismiss$1) and SearchPageState were ALL present and reachable in the real release dex. Conclusion: R8's isOptimizeCode legitimately inlined this small, single-call-site composable into its caller (SearchResultScreenKt) — a correct optimization, not a stripped/broken feature. Real users hit the working inlined code path through the normal SearchResultScreen navigation flow. Added a targeted -keep rule so the isolated component test (a legitimate test pattern, calling the reusable composable directly rather than through full navigation) has a stable class to reference. This is NOT a product defect fix — the feature was never broken for real users; only the isolated test's ability to name the class was affected.
