## Scope — this cycle's real changes

1. **lava-api-go 2.3.34 → 2.3.35**: fixed a real `:8443` port collision with an
   unrelated process on a shared host (`server.ResolveListen()` + a new
   race-free `network.ListenEphemeral` helper added to `submodules/containers`),
   and a genuine mDNS/Alt-Svc-before-any-bind ordering bug found while
   investigating it. No `:app` module source changed for this reason — the
   client consumes lava-api-go only via the embedded on-device engine in
   `:api-app`, not directly.
2. **Release-variant device-testing gap closed** (this same commit, `c4e05e51`):
   this project previously had NO way to run Challenge/instrumentation tests
   against the R8-minified release-shaped APK for either app. A new
   `releaseTest` Gradle build type (AndroidX-Benchmark pattern) plus 8 real,
   individually-discovered R8 minification fixes in `app/proguard-rules.pro`
   make this genuinely possible for the first time. This is real production
   proguard-rules.pro content and therefore affects the actual shipped
   `release` build too (built and verified below), even though it was
   discovered via the test-only `releaseTest` variant.
3. Two governance gate-integrity bugs (substring-match exploits in
   `scripts/check-constitution.sh`) and a Robolectric/JDK host-compatibility
   fix — neither touches `:app` runtime source.

**Net effect on `:app`'s own Kotlin/Compose source:** no behavior change.
**Net effect on the actual shipped `release`/`debug` `:app` APKs:**
proguard-rules.pro additions only affect what R8 keeps, never removes
anything the app itself needs — verified below by running the SAME Challenge
against both variants, not merely by reasoning about the diff.
