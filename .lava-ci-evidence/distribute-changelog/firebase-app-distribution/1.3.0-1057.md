# Lava-Android-1.3.0-1057 — 2026-06-04 (Client ↔ API-app linking + onboarding "On this device")

**Previous published:** Lava-Android-1.2.36-1056 (debug).

New feature — connect the Lava client and the on-device Lava API app to each other:

- **Onboarding "Choose your API" → "On this device"** section: launch the Lava API app
  right from onboarding ("Open Lava API app"), or, if it isn't installed, go to the
  Firebase download page ("Install Lava API app") — no dead Play-Store links (the API app
  ships via Firebase, not Google Play).
- The API app **auto-starts its engine** when opened this way and offers **"Back to Lava
  client"**; the client then **auto-connects** to the on-device API over loopback (with the
  on-device API's key handed over securely via a same-signature ContentProvider).
- **Bidirectional**: the API app has an **"Open Lava client"** button (install via Firebase
  if absent).

Fixes (operator-reported 2026-06-04, verified on a real Samsung S23 Ultra):

- **Bug A — "Could not reach this API: API did not respond"** when selecting the locally
  running, discovered on-device API. Root cause: the discovered endpoint carried a doubled
  port (`192.168.31.119:8443:8443`) so the connection target host was invalid. Fixed — the
  discovered host is now the bare IP; selecting it connects and advances.
- **Bug B (api-app side, shipped in 0.2.0-4)** — re-opening the API app no longer tries to
  re-start the engine ("address already in use"); it shows the live running state.

Known (this build): selecting the **cloud API** (lava.app) may return an auth error until the
cloud server registers this version — it's being updated separately. Testing the **on-device**
Lava API (the new "On this device" linking) is unaffected.
