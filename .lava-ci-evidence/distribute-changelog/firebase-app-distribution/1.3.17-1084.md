# Lava-Android-1.3.17-1084 — LVA-085 x LVA-093 composition race, closed on both chip bars

**Previous published:** Lava-Android-1.3.16-1083.

- **Root cause:** LVA-085 (raw provider ids in chips) and LVA-093 (cold-start readiness gate) landed in 1083, each individually unit-tested, never tested together. `SearchResultViewModel` read the tracker registry for display names BEFORE awaiting the readiness gate, so a genuine cold-start search could still show raw provider ids.
- **Fix #1 (`SearchResultViewModel`, results screen):** commit `843f8107`. Moved the readiness-gate wait before the display-name resolution.
- **Fix #2 (`SearchInputViewModel`, input screen — a second, independent instance):** commit `8634efd9`. This ViewModel never had a readiness gate at all. Added one, mirroring fix #1.
- **Device-verified, not just JVM-tested:** `Challenge61ResultsChipsShowDisplayNamesTest` + `Challenge59SearchUsesOnboardedProvidersTest` both PASSED on a containerized KVM emulator against this exact build.
